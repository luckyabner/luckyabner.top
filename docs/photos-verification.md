## 加载性能

测试素材为三张 Unsplash 公共照片重复组成的 39 张照片，**仅存在于临时测试副本，不提交、不发布**。这不是用户实拍照片的最终画质或线上性能验收。

采用本机静态服务器、文本 gzip、`Cache-Control: no-store`，并使用浏览器原生 PerformanceObserver 与 Resource Timing。手机场景通过服务器限制**合计吞吐 200,000 字节／秒（1.6 Mbps），每个响应额外延迟 150ms**。这是可控的传输测试，不等同于 DevTools 的完整移动网络与 CPU 仿真。浏览器 DPR 为 1，没有模拟手机高像素密度。

每个场景为单次测量；请求及字节仅统计本站来源，包含文档及浏览器提前请求的附近缩略图，不包含外部 Umami 请求。

浏览器的原生懒加载会提前请求视口附近的图片，不能将这些请求数理解为屏幕内实际可见照片数；响应式图片候选变化也可能产生额外请求。

生产构建中，照片页脚本约 **5.99 kB gzip**，PhotoSwipe 核心独立约 **17.49 kB gzip**，后者在第一次打开照片时加载。缩略图和大图使用预生成 WebP，未经过 Astro 二次转码。

本次受限传输测量达到方案中的 LCP ≤2.5s、CLS ≤0.05 目标。仍需在加入真实照片、部署到真实 CDN 后测量；这里没有现场 INP、CPU 降速、高 DPR 或真实移动设备性能结论。Vercel 长缓存规则已配置，尚未部署验证线上响应头。
