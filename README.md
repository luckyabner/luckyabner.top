# My blog

## Photos

照片页位于 `/photos`。页面静态生成，图片随网站发布，无需图床或在线图片处理服务。

### 日常发布

1. 将调色软件的导出目录固定为项目内的 `.photos-local/inbox/`，可以按旅行建立子目录。
2. 建议导出 **sRGB JPEG**，保留拍摄时间、相机／镜头及拍摄参数。也支持 PNG、WebP，不支持 RAW、动画或多页图片。
3. 运行 `pnpm photos:prepare`，首次运行会自动创建本地目录。脚本只读取原片，永不移动、覆盖或删除原片。
4. 运行 `pnpm dev`，打开 `/photos` 检查构图和清晰度。
5. 提交 `public/photos/`、`src/data/photos.json` 和需要修改的 `src/data/photos.meta.json`，然后按现有流程部署。

`.photos-local/` 已被 Git 忽略。这里的原片和处理缓存不进入仓库，也不会进入网站部署；原片仍需自行备份和归档。压缩后的图片进入 Git，仓库仍会随照片增长；脚本每次会报告发布目录的总大小。

### 标题、描述、日期与下架

编辑 `src/data/photos.meta.json`，以原片相对导出目录的路径作为键，例如：

```json
{
  "trip/DSC01234.jpg": {
    "title": "海边",
    "description": "傍晚的海浪拍打岸边的岩石。",
    "date": "2026-10-20",
    "published": true
  }
}
```

以下字段均可省略（`location` 见下文“拍摄地点与地图”）：

- `title`：大图浏览时显示的标题，也可作为描述的后备值。
- `description`：图片替代文本，建议描述照片内容。没有描述或标题时暂用日期和编号，脚本会提示补充。
- `date`：拍摄日期，支持 `YYYY-MM-DD` 或带时区的 ISO 时间戳；优先于 EXIF 拍摄时间。两者都缺失时使用首次导入时间，后续运行不会改成当天。
- `published`：默认 `true`；设为 `false` 后从照片墙下架。**这不等于撤回公开文件**，已有图片链接仍可访问。

编辑后运行 `pnpm photos:prepare` 更新清单。原片已归档时，也可以只修改元数据并运行此命令。

### 拍摄地点与地图

照片页右上角的 **Map** 可切换到地图视图（链接 `/photos#map`）。地图上每个点是照片的圆形缩略图，相近的照片按屏幕距离合并并显示数量；点击合并点会放大到能分开为止，同一地点的照片直接在灯箱中浏览，灯箱底部显示地点名称。没有坐标的照片只出现在网格中；一张都没有时不显示 Map 按钮。地图和瓦片只在第一次切换到地图时加载。

地点只能手动标记（EXIF 中的 GPS 仍然不会发布）：

1. 运行 `pnpm dev`，打开 <http://localhost:4321/photos/locate>。此页面和它的写入接口只在开发服务器中存在，不会进入生产构建。
2. 在左侧勾选一张或多张照片（可筛选“Only unlocated”），在地图上方搜索地点并选择结果，或者点击地图、粘贴 `纬度, 经度`。可拖动标记微调，再填写可选的地点名称（选择搜索结果时会自动填入）。点击缩略图可查看大图：`←` `→` 按列表顺序翻图，点击图片在“适应窗口”和“原始尺寸”之间切换。
3. 点击 **Save to selected**，坐标写入 `src/data/photos.meta.json` 并同步到 `src/data/photos.json`，不重新处理图片。**Use last saved** 可沿用上一次的位置，点击地图上已有的点可选中该地点的照片，**Remove location** 删除坐标。
4. 提交这两个 JSON 文件。

也可以直接编辑 `photos.meta.json` 后运行 `pnpm photos:prepare`：

```json
{
  "trip/DSC01234.jpg": {
    "location": { "lat": 30.2431, "lng": 120.15, "name": "杭州 · 西湖" }
  }
}
```

- 坐标使用 **WGS-84**，最多 4 位小数（约 10 米），编辑器保存时自动取整。从高德、百度等国内地图复制的坐标带有 GCJ-02 / BD-09 偏移，建议直接在编辑器的地图上点选。
- 编辑器会识别顺序填反的 `经度, 纬度`（高德、百度复制出来就是这个顺序）并自动交换，状态栏会提示。有一个数值超过 90 时可以确定顺序；两个数值都在 ±90 以内时（如新疆、西藏、欧洲），地图放大后按离当前视野更近的解读，否则保持原样，粘贴后请核对标记位置。
- 地点搜索使用 OpenStreetMap 的 Nominatim，无需 key，通过开发服务器转发，按回车才搜索，每秒最多一次。结果优先显示英文名称（选择后也以英文填入地点名称），没有英文名时显示中文；中英文都可以搜索。知名景点和城市基本都能找到；国内小店、新地点的数据较少，搜不到时可改用“地点, 城市”的写法（如 `West Lake, Hangzhou` 或 `西湖 杭州`），或直接在地图上点选。
- `name` 可选，最多 80 个字符。
- 保存后页面不会整页刷新：`astro.config.mjs` 里把 `src/data/photos.json` 和 `src/data/photos.meta.json` 排除在开发服务器的文件监听之外（否则每次保存都会触发全页重载、丢掉列表滚动位置）。代价是手动改这两个文件后要自己刷新浏览器。
- 坐标会公开发布。住处等私人地点建议只标到城市级别，或不标记。

底图使用 CARTO Positron（浅色主题）和 Dark Matter（深色主题），自 2026 年 9 月起需要 API Key：在 <https://carto.com/basemaps/apikey> 免费申请（非商业用途每月 500 万次请求），然后在本地 `.env` 和 Vercel 项目环境变量中设置：

```sh
PUBLIC_CARTO_BASEMAPS_KEY=你的 key
```

这个 key 会出现在公开的瓦片地址中，这是浏览器直接请求瓦片的必然结果。未设置时地图仍可使用，但瓦片带有 “API key required” 水印。地图须保留 “© OpenStreetMap contributors, © CARTO” 署名。

### 更新、归档和图片处理

- **重新调色：** 导出到相同的相对路径再运行脚本，照片 ID 和首次导入时间保留，图片 URL 随内容变化。更改文件名或子目录会被视为新照片；旧照片可通过元数据下架。
- **归档原片：** 处理完成后可以把本地原片移走。脚本不会因为找不到原片而移除已发布照片。
- **增量处理：** 未变化的源文件与生成参数不会重新编码，重复运行不改写清单或图片；缺失的生成图片会在原片仍在时重建。
- **处理规格：** 每张照片只生成两份：宽 960px 的缩略图（WebP 质量 80），以及最长边 2560px 的大图（质量 88）。保留原比例、不放大小图，极窄竖图缩略图也限制最长边 2560px。自动处理 EXIF 旋转和 sRGB 转换，不保留原始 ICC 配置。
- **拍摄参数：** 缩略图不含 EXIF；大图仅写入相机／镜头品牌型号、拍摄时间、光圈、快门、ISO、焦距及 35mm 等效焦距（源图有时才保留）。清单记录同样的参数，大图底部直接显示，无需浏览器再读取图片元数据。GPS、设备序列号、MakerNotes、XMP、IPTC 等不会发布。已归档原片的照片保留现有输出；若要补充参数，需要把原片放回导出目录后再运行处理。
- **文件命名：** 例如 `2025-06-01_16-43-15_0007-1234abcd-thumb.webp` 和同前缀的 `-large.webp`。前缀保留 EXIF 拍摄时刻的相机本地时间，优先读取 DateTimeOriginal，其次 CreateDate；都没有时使用首次导入时间。编号区分同一秒拍摄的照片，8 位内容校验码用于更新缓存。手动覆盖展示日期不会重命名已生成的文件。
- **时间：** EXIF 没有时区时按运行脚本的电脑本地时区解释；对日期有严格要求时在元数据中明确指定。
- **安全发布：** 单张图片全部转换成功才更新清单，失败时保留之前的发布版本并返回失败状态。清单更新成功后，已被替代的旧生成文件移到 `.photos-local/previous-exports/` 下的独立备份目录，不再占用公开发布目录；不会处理不属于原清单的其他文件，也不会改动原片。原片已归档的旧四份输出可直接选取现有 960px 缩略图和大图进行迁移，无需重新导入原片。
- **缓存：** 生成文件名包含内容及处理参数的哈希，Vercel 为 `/photos/*.webp` 配置一年缓存；更新图片会使用新 URL。

普通构建不运行导入脚本，只检查已经提交的照片清单与图片，远程部署无需本地原片。

照片页的 Full frame 使用无框取景框按钮：开启时文字加深、图标变为横幅构图。点击照片按需加载 PhotoSwipe；加载失败会直接打开大图文件。灯箱参数随切图更新，缺失的项目自动略过。按 Esc 关闭后恢复原位置和焦点。

```sh
pnpm photos:prepare  # 导入／更新照片及元数据
pnpm photos:check    # 验证清单、图片尺寸、体积及隐私元数据
pnpm test:photos     # 在系统临时目录测试导入和归档流程
pnpm build          # 先检查照片，再构建整个网站
```

实现与性能验证的范围、数据及限制见 [Photos 验证记录](docs/photos-verification.md)。
